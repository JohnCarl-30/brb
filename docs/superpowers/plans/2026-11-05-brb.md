# brb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and ship `brb`. It's one command, plus a Claude Code plugin, that shows a catch-up of every Claude Code, Codex CLI and Gemini CLI session and of your own uncommitted edits when you come back.

**Architecture:**
- Three read-only adapters turn each tool's local history files into one `Session` model made of normalized events.
- A pure classifier gives each session a status.
- A pure `buildCatchUp` groups sessions into HERE and ELSEWHERE, keeps what moved while you were away, and picks next steps.
- Renderers print the result for people (terminal), for agents (`--brief`, used by the Claude hook) and for scripts (`--json`).
- Optional one-line AI summaries go only to each session's own tool CLI and are cached.

**Tech Stack:** TypeScript 5 (ESM) on Node ≥ 20, `node:util` `parseArgs`, picocolors (bundled), tsup (single file `dist/brb.mjs`), vitest, tsx (demo seeding), VHS (demo GIF), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-05-brb-design.md`. Read it first. References like §7.2 point to it.

**Where to work:** a permanent folder the owner picks (e.g. `~/Documents/GitHub/brb`), never a temporary one.

## Global Constraints

- TypeScript on Node (current LTS, ≥ 20). Published to npm as `brb` so `npx brb` works with nothing installed. MIT license.
- One repo holds the core library, the CLI and the Claude Code plugin. The repo root is the plugin root. `dist/brb.mjs` is committed so the plugin can run it.
- macOS and Linux at launch. Windows best-effort, so use `node:path` everywhere.
- Useful output with no API key, account or config file.
- brb makes no network calls of its own. Optional summaries send a session's text only to the AI tool that session came from (§7.5).
- Strictly read-only toward every agent's data. brb writes only under `$BRB_HOME` (default `~/.brb`) and `<os tmpdir>/brb-summaries`.
- Facts render in under 1 second on a machine with ~100 projects of history. AI summaries never block facts.
- A tool whose files can't be read is skipped with one warning: `Couldn't read <Tool> sessions: <reason>`.
- Never guess "waiting". When unsure, the status is `idle`.
- Read only files changed in the last 7 days. Waiting sessions stay visible for those 7 days. A first run with no history looks back 8 hours.
- The Claude hook's text is at most 10 lines and empty when nothing is relevant.
- Test data and the demo are hand-made. Never copy real session content into the repo.
- Fixed copy, used verbatim by README and tests:
  - `HERO` = ``Step away from your AI coding sessions. When you're back, `brb` shows you everything that moved in one screen.``
  - `POSITIONING` = ``Claude Code's `/recap` knows one Claude session. `brb` knows all of them, plus Codex, Gemini and your own edits.``
  - `PRIVACY` = ``brb reads local files only and makes no network calls of its own. No API key. If you have an AI CLI installed, brb can ask it for one-line summaries, and a session's text only ever goes back to the AI tool it came from. Turn this off with `--no-ai` or `BRB_NO_AI=1`.``
- Owner's git rules:
  - Name branches `<topic>-<4 random hex>`.
  - `main` on GitHub changes only through a pull request.
  - Ask the owner before every push and before anything public (repo creation, npm publish, posts).

## Review Focus

1. **Terminal control codes in session text.** Command output or titles may contain escape codes, colors or newlines. They must print as clean single lines that never clear the screen or move the cursor. Test: Task 9 `strips terminal control codes from session text`.
2. **Files being written right now.** A half-written last line, or a read window that starts mid-line, is skipped and nothing throws. Test: Task 3 `survives half-written lines`.
3. **Long sessions.** When the last human message is outside the bytes brb reads, brb stays fast, takes status only from what it read, and never guesses "waiting". Tests: Task 3 `survives half-written lines` and the Task 6 bench.
4. **Outside a repo, or in a repo with no commits.** No crash. Outside a repo there's no HERE section. With no commits, the You row still works. Tests: Task 7 `works in a repo with no commits yet`, Task 10 `works outside any git repo`.
5. **A deleted session folder (removed worktree).** The session is still listed under its recorded path, with a resume command that `cd`s there. Test: Task 6 `falls back to the recorded path when the folder is gone`.

```ts
export type Tool = 'claude' | 'codex' | 'gemini';
export type Status = 'waiting' | 'finished' | 'failed' | 'working' | 'idle';
export type SessionEvent =
  | { kind: 'user'; at: number; text: string }                  // a prompt the human typed
  | { kind: 'agent'; at: number; text: string }                 // prose the agent showed the human
  | { kind: 'edit'; at: number; files: string[] }               // absolute paths the agent changed
  | { kind: 'command'; at: number; command: string; ok: boolean; output: string }
  | { kind: 'ask'; at: number; reason: 'question' | 'plan'; text: string } // structured ask, still unanswered
  | { kind: 'error'; at: number; text: string }                 // API error, interrupt, cancel
  | { kind: 'turn-end'; at: number };                           // the agent finished its turn
export interface Session {
  tool: Tool;
  id: string;              // what the tool's resume command accepts
  cwd: string;             // absolute folder the session ran in
  title: string;           // ≤ 60 chars, already cleaned
  branch?: string;
  events: SessionEvent[];  // chronological
  lastActivityAt: number;  // last event's `at`, or the file mtime when there are no events
}
export interface PermissionRequest { at: number; message: string }
export interface Verdict { status: Status; detail: string; longText: string }
```

- [ ] **Step 8: Implement `classify` in `src/classify.ts`.** The rules follow §7.2. Apply them in order; the first match wins. One refinement: a turn that has ended is never `working`, even within 60 s. §7.2 only looked at when the file was last written, which would show a session that just finished as "working".

```
turn = events after the last 'user' event (all events if none); last = last event of turn
said = text of the last 'agent' event in turn ('' if none)
1. permission && permission.at >= s.lastActivityAt - 2_000  → waiting, permission.message
2. an 'ask' in turn        → waiting, reason 'plan' ? 'has a plan waiting for your approval' : `asks: "${text}"`
3. last?.kind === 'error'  → failed, last.text
4. last?.kind !== 'turn-end' → (now - s.lastActivityAt < 60_000)
       ? working, firstSentence(said) || 'working…'
       : idle, `no activity for ${formatAge(now - s.lastActivityAt)}`
5. the last 'command' in turn has ok false → failed, errorLine(output) || `${command} failed`
6. no 'edit' or 'command' in turn && lastQuestion(said) → waiting, `asks: "${question}"`
7. otherwise → finished, firstSentence(said) || 'done'
longText = rule 5: `${command}\n${output.slice(-1500)}`; rule 3: last.text; otherwise said
```

```ts
export interface FakeHome { home: string; claude: string; codex: string; gemini: string; brb: string }
export function makeFakeHome(): FakeHome   // mkdtemp in fs.realpathSync(os.tmpdir()); folders = <home>/.claude .codex .gemini .brb
export const iso = (ms: number) => new Date(ms).toISOString();
export const cl = {
  user: (text: string, at: number) => ({ type: 'user', timestamp: iso(at), promptSource: 'sdk', turnOrigin: 'human', message: { role: 'user', content: text } }),
  notice: (text: string, at: number) => ({ type: 'user', timestamp: iso(at), promptSource: 'system', turnOrigin: 'task_notification', message: { role: 'user', content: text } }),
  say: (text: string, at: number, stop: 'end_turn' | 'tool_use' = 'end_turn') => ({ type: 'assistant', timestamp: iso(at), message: { role: 'assistant', content: [{ type: 'text', text }], stop_reason: stop } }),
  tool: (id: string, name: string, input: object, at: number) => ({ type: 'assistant', timestamp: iso(at), message: { role: 'assistant', content: [{ type: 'tool_use', id, name, input }], stop_reason: 'tool_use' } }),
  result: (id: string, content: string, at: number, isError = false) => ({ type: 'user', timestamp: iso(at), message: { role: 'user', content: [{ type: 'tool_result', tool_use_id: id, content, is_error: isError }] } }),
  title: (customTitle: string) => ({ type: 'custom-title', customTitle }),
  apiError: (at: number) => ({ type: 'system', subtype: 'api_error', timestamp: iso(at) }),
};
export function writeClaudeSession(h: FakeHome, o: { id: string; cwd: string; branch?: string; lines: object[]; sidechain?: number[]; mtimeMs?: number; filler?: number }): string
```

`writeClaudeSession` details:
- **Path:** `<h.claude>/projects/<o.cwd with every char outside [A-Za-z0-9] replaced by '-'>/<o.id>.jsonl`.
- **Fields added to every line:** `sessionId`, `cwd`, `gitBranch` (`o.branch ?? 'main'`), `uuid` (`u<index>`), and `isSidechain` (true for indexes listed in `o.sidechain`).
- **`o.filler`:** about that many bytes of `cl.result('pad', 'x'.repeat(4000), …)` lines, stamped with the first line's time and inserted after the first line.
- **mtime:** `o.mtimeMs`, or else the newest timestamp.
- **Returns:** the file path.

|---|---|

| `type:'user'`, content is a string or text blocks, text starts with `[Request interrupted by user` | `error` `interrupted` |
